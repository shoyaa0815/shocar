# Shocar

เว็บเซิร์ฟเวอร์พื้นฐาน เปิดหน้าเว็บเปล่าที่ `/` ผ่าน HTTP
เปิดหน้า dashboard ได้ที่ `/dashboard`
เปิดหน้ารีโมทได้ที่ `/remote` และส่งคำสั่งผ่าน WebSocket `/ws/remote`
รับภาพจากแอป IP Webcam บน Android ผ่าน Python แล้วแสดงบน dashboard ได้
มีโหมดทดลองประเมินความลึกด้วย Depth Anything V2 Small และปุ่มเริ่ม–หยุดขับอัตโนมัติจากกรอบซ้าย–ขวาบน Dashboard
ช่องภาพที่ 3 "ตรวจจับสิ่งของ / ไม่กรองระยะ" ใช้ YOLOE Small ตีกรอบสีส้มรอบสิ่งของและเฟอร์นิเจอร์ทั่วภาพ ไม่แสดงชื่อหรือคะแนน และไม่ใช้ผลนี้สั่งรถ
เส้นสีฟ้าไปพื้นไกลสุดยังแสดงได้เมื่อมีผลความลึกจากภาพเดียวกัน ระยะเป็นเพียงค่าประมาณ

## เริ่มใช้งาน

```bash
venv/bin/python main.py
```

เปิด http://localhost:8000/ ในเบราว์เซอร์ และกด Ctrl+C เพื่อหยุด
รองรับ `--host` (ค่าเริ่มต้น `0.0.0.0`) และ `--port` (ค่าเริ่มต้น `8000`)
ไม่ต้องใช้ไฟล์ cert/key

## โครงสร้างเซิร์ฟเวอร์

- `main.py` — รับค่า host/port และเริ่ม Uvicorn
- `server/app.py` — สร้าง FastAPI โหลด `.env` และจัดการเริ่ม/หยุดตัวรับภาพ
- `server/routes/pages.py` — เปิดหน้าเว็บ `/`, `/dashboard`, `/remote`
- `server/routes/camera.py` — ส่งภาพและสถานะผ่าน WebSocket `/ws/viewer`
- `server/routes/remote.py` — รับคำสั่งผ่าน WebSocket `/ws/remote` และจัดการสิทธิ์ควบคุมรถ
- `server/services/` — ตัวรับภาพ `camera_stream.py` และตัวส่งคำสั่งรถ `robot_control.py`
- `server/pages/` — ไฟล์ HTML ของ dashboard และรีโมท
- `server/ai_brain/` — รันโมเดลความลึก (`depth_model.py`), ทดลองแยกสิ่งกีดขวางจากพื้น (`detector.py`) และประมาณระยะพื้นเป็นเซนติเมตร (`range.py`)
- `server/services/vision_preview.py` — worker ความลึกหนึ่งชุดร่วมกันทุก Dashboard
- `server/services/object_preview.py` — worker ตรวจจับสิ่งของสำหรับช่อง 3 ร่วมกันทุก Dashboard แยกจากระบบขับรถ
- `server/ai_brain/object_model.py` — โมเดล YOLOE Small แบบ prompt-free และตัวกรองคน/พื้นผิว
- `server/ai_brain/navigation.py` — ตัดสินทิศทางจากกรอบซ้าย–ขวาและยืนยัน 3 เฟรมใหม่
- `server/services/auto_drive.py` — ควบคุมโหมดอัตโนมัติและตรวจภาพ/ผลวิเคราะห์/heartbeat
- `server/routes/auto_drive.py` — รับเริ่ม–หยุดและสถานะผ่าน `/ws/auto`
- `scripts/download_depth_model.py` — ดาวน์โหลดโมเดล Small พร้อมตรวจ SHA256
- `scripts/download_object_model.py` — ดาวน์โหลด YOLOE Small prompt-free พร้อมตรวจ SHA256

## กล้องมือถือผ่าน IP Webcam

1. เปิดฮอตสปอตบนมือถือ แล้วให้คอมเชื่อมต่อ
2. เปิดแอป IP Webcam เลือกกล้องหลัง เริ่มที่ 640×480 และ 15 FPS ถ้ามีตัวเลือก แล้วกด **Start server**
3. เปิด IPv4 URL ที่แอปแสดงจากเบราว์เซอร์บนคอม เพื่อตรวจว่าเห็นภาพ
4. เพิ่ม URL จริงใน `.env` เช่นด้านล่าง (เลขนี้เป็นเพียงตัวอย่าง):

```dotenv
CAMERA_URL=http://192.168.43.1:8080
```

ใส่ที่อยู่หลักตามแอปได้เลย ระบบเติม `/video` ให้ หรือระบุ URL สตรีม MJPEG เต็ม
เช่น `http://192.168.43.1:8080/video` หากตั้งรหัสผ่านในแอป สามารถใช้
`http://user:password@192.168.43.1:8080/video` (อักขระพิเศษในชื่อ/รหัสต้อง URL-encode)
เก็บข้อมูลนี้ใน `.env` ของเครื่องเท่านั้น

5. รัน `venv/bin/python main.py` แล้วเปิด http://localhost:8000/dashboard

หลังแก้ `.env` ให้หยุดและเริ่ม server ใหม่ ค่าจาก Terminal มีลำดับความสำคัญกว่า `.env`
ถ้าไม่ตั้ง `CAMERA_URL` หรือเว้นว่าง เว็บและรีโมทยังเปิดได้ แต่ dashboard จะแจ้งให้ตั้งค่ากล้อง
URL ที่ไม่ใช่ HTTP/HTTPS จะถูกปฏิเสธตอนเริ่ม server

Python เปิดสตรีมกล้องร่วมกันหนึ่งชุดสำหรับทุก dashboard เก็บภาพล่าสุดในหน่วยความจำ
ไม่บันทึกวิดีโอ และไม่ส่งภาพไป cloud ถ้ารับภาพไม่ได้จะลองใหม่ทุก 2 วินาที
ถ้าไม่มีภาพใหม่ภายใน 3 วินาที จะระบุว่าภาพไม่สด ภาพเก่าที่แสดงจึงไม่ถูกนับเป็นภาพสด
ปิด dashboard แล้วตัวรับภาพยังทำงาน หยุดด้วย Ctrl+C พร้อม server
ใช้ server หนึ่ง process เท่านั้น

อัตรารับภาพที่แสดงเป็น FPS ล่าสุดที่ Python รับได้ ไม่ใช่ FPS ของ AI
อายุภาพนับจากเวลาที่ Python รับภาพ ไม่ใช่ความหน่วงจากกล้องถึงหน้าจอทั้งหมด
ยังต้องวัดความหน่วง ความร้อน และความเสถียรกับมือถือ/ฮอตสปอตจริง

ทดสอบจริง: เปิดภาพ 10 นาที ขยับวัตถุหน้ากล้อง จากนั้นหยุด IP Webcam
ตรวจว่า dashboard แจ้งภาพไม่สดภายในประมาณ 3 วินาที แล้วเปิดกล้องอีกครั้ง
ภาพควรกลับมาเองโดยไม่ต้องรีเฟรชหน้า ถ้าเชื่อมต่อไม่ได้ ให้ตรวจ URL และการเชื่อมต่อฮอตสปอต

ทดสอบตัวรับภาพและเว็บด้วยกล้องจำลอง:

```bash
venv/bin/python -m unittest discover -s tests -p 'test_camera_stream.py' -v
```

## ทดลองความลึกจากกล้องเดียวโดยยังไม่ต่อรถ

ใช้ **Depth Anything V2 Small** ประเมินความลึกเชิงเปรียบเทียบจากภาพมือถือ
รันด้วย PyTorch ในคอม ไม่ต้องฝึกโมเดล ไม่ต้องจำสีพื้น และไม่ต้องติดตั้ง ORB-SLAM/ROS
ใช้ dependencies `torch`, `torchvision`, `opencv-python`, `numpy` ที่อยู่ใน requirements เดิม

ดาวน์โหลดโมเดลครั้งแรก (ประมาณ 99 MB ต้องใช้อินเทอร์เน็ต):

```bash
venv/bin/python scripts/download_depth_model.py
venv/bin/python main.py
```

สคริปต์ตรวจ SHA256 และบันทึกที่ `models/depth_anything_v2_vits.pth` ซึ่งไม่เข้า Git
เวอร์ชันโมเดลและ source ของผู้พัฒนาถูกตรึงไว้ ดู `server/ai_brain/vendor/README.md`
หลังดาวน์โหลดแล้ว การเปิด server และวิเคราะห์ภาพไม่ใช้อินเทอร์เน็ตและไม่ส่งภาพขึ้น cloud
ใช้ GPU CUDA หากพร้อม ไม่เช่นนั้นใช้ CPU (input 518 บน CUDA / 392 บน CPU)
โมเดลโหลดเมื่อมีภาพสดครั้งแรก เว็บยังเปิดได้แม้โมเดลหายหรือโหลดไม่ได้

เปิด `/dashboard` จะเริ่มวิเคราะห์อัตโนมัติ การตั้งค่าการแสดงผลไม่หยุดการวิเคราะห์
สีสว่างในภาพความลึกหมายถึงใกล้กว่า
สีมืดหมายถึงไกลกว่า ภาพความลึกเองยังไม่แสดงระยะเป็นเซนติเมตรหรือเมตร

จอ 1 ใช้ความกว้างเต็มแถวของส่วนภาพ จอ 2 และ 3 เรียงต่อด้านล่าง
เปิด **ตั้งค่าการแสดงผลจอ 1** มี 4 ตัวเลือก: กรอบซ้าย–ขวาพร้อมป้าย LEFT/RIGHT,
กรอบจากความลึก, กรอบสิ่งของ และเส้นพื้นไกลสุดพร้อมตัวเลขระยะ มีปุ่มเปิดทั้งหมด/ปิดทั้งหมด
ค่าเริ่มต้นเปิดทุกส่วนและจำค่าด้วย localStorage เฉพาะเบราว์เซอร์และที่อยู่เว็บนี้
ถ้าเบราว์เซอร์ไม่อนุญาตให้เก็บค่า ยังใช้ตัวเลือกได้ระหว่างเปิดหน้า

จอ 1 เลือกภาพต้นฉบับที่ตรงกับผลที่แสดงและวาดส่วนเสริมใน Canvas
เมื่อปิดทั้งหมดจะใช้ภาพกล้องล่าสุดที่ไม่มีกรอบติดมา ผลที่ไม่มีภาพคู่กันหรืออายุครบ 3 วินาทีจะไม่ถูกวาด
ผลความลึกที่มากับภาพตรวจจับใช้พิกัดที่แปลงเป็นขนาดภาพเดียวกัน ไม่ใช้กรอบจากเฟรมอื่นมาซ้อน
จอ 2–3 และสถานะ/คำสั่งขับรถไม่ขึ้นกับตัวเลือกเหล่านี้ เส้นชี้และระยะสิ่งของยังไม่แสดง
หลังอัปเดตนี้ต้องเริ่ม server ใหม่เพื่อส่งภาพต้นฉบับและข้อมูลประกอบเพิ่มเติม แล้วโหลดหน้า dashboard ใหม่

- เขตเฝ้าระวังคงที่: แนวนอน 0–100% ชิดขอบซ้ายและขวาของภาพ แนวตั้ง 50–95% แบ่งครึ่งเป็นซ้าย–ขวาที่กึ่งกลางภาพ
- สีแต่ละช่องเปลี่ยนแยกกัน ของอยู่ซ้ายทำให้ช่องซ้ายแดง อยู่ขวาทำให้ช่องขวาแดง และคร่อมกลางทำให้แดงทั้งคู่
- เมื่อแยกพื้นไม่ได้ ช่องที่พบวัตถุใกล้ยังเป็นแดงได้ ส่วนช่องที่ยังยืนยันไม่ได้จะเป็นเหลือง
- กรอบสิ่งกีดขวางจากความลึก: บริเวณที่คาดว่าเป็นสิ่งกีดขวางใกล้ อาจมีทั้งในและนอกกรอบใหญ่
- ช่องแดง: มีบริเวณสิ่งกีดขวางใกล้ซ้อนเข้ามาในเขตเฝ้าระวัง
- ช่องเขียว: ยังไม่ตรวจพบสิ่งกีดขวางใกล้ในเขต ไม่ยืนยันว่าทางปลอดภัย
- ช่องเหลือง/สถานะประเมินไม่ได้: พื้นไม่ชัดและยังยืนยันวัตถุใกล้ไม่ได้ โมเดลไม่พร้อม หรือภาพ/ผลวิเคราะห์เก่า

### ช่อง 3: ตีกรอบสิ่งของโดยไม่กรองระยะ

ดาวน์โหลดโมเดลสำเร็จรูปครั้งเดียวก่อนเริ่ม server:

```bash
venv/bin/python scripts/download_object_model.py
```

ใช้ [YOLOE-v8s-seg-pf](https://docs.ultralytics.com/models/yoloe/) จาก Ultralytics (ประมาณ 30 MB)
มีคำศัพท์ในตัว 4,585 ชื่อ ไม่ต้องฝึกโมเดลหรือดาวน์โหลด text encoder เพิ่ม รันบน CPU หรือ CUDA ในเครื่อง
ตัว server ตรวจว่ามีไฟล์ก่อนโหลดและไม่ดาวน์โหลดโมเดลเอง ไม่ส่งภาพไปบริการ AI ภายนอก
โมเดลและ dependency มีสิทธิ์การใช้งานของผู้พัฒนาเดิม ดู [Ultralytics](https://github.com/ultralytics/ultralytics)

- ตรวจสิ่งของและเฟอร์นิเจอร์ทั่วภาพ ไม่กรองตามความลึก เขตเฝ้าระวัง การเห็นพื้น หรือช่วงระยะเซนติเมตร
- กรองชื่อประเภทคนและพื้นผิว เช่น พื้น ผนัง เพดาน ประตู หน้าต่าง ออกจากผลโมเดล
- แสดงเฉพาะกรอบสีส้มรอบสิ่งของ ไม่แสดงเส้นชี้ ระยะสิ่งของ ชื่อ หรือคะแนนความมั่นใจ ใต้ภาพแสดงจำนวนที่ตรวจได้
- ภาพช่อง 3 เป็นภาพเดียวกับที่ใช้ตรวจจับ กรอบจึงไม่ถูกวางบนภาพสดที่ใหม่กว่าผลวิเคราะห์
- มี worker หนึ่งชุดร่วมกันทุกผู้ชม จำกัดสูงสุด 2 รอบ/วินาที เลือกภาพล่าสุดโดยไม่สะสมคิว อัตราจริงขึ้นกับ CPU/GPU
- แยกจาก worker ความลึก ช่อง 1–2 และ AutoDrive ยังใช้ความลึกและเงื่อนไขเดิม ผล YOLOE ไม่ถูกส่งไปสั่งรถ
- ถ้าผลความลึกสดพร้อมใช้ จะนำภาพต้นทางของผลนั้นมาตรวจจับด้วย เพื่อแสดงเส้นพื้นไกลสุดบนเฟรมเดียวกัน
  ถ้าความลึกไม่พร้อม จะตรวจจากภาพกล้องโดยตรงและซ่อนเส้นฟ้า กรอบสิ่งของไม่ต้องรอโมเดลความลึก
- ภาพ/ผลอายุครบ 3 วินาทีหรือกล้องหลุด จะล้างกรอบ เส้น และป้ายระยะพร้อมกัน หากโมเดลขัดข้องจะแจ้งเหตุผล แยกจากกรณีตรวจสำเร็จแต่ยังไม่พบสิ่งของ

เส้นสีฟ้าเลือกพื้นจากความลึกที่สอดคล้องกับระนาบพื้นและต่อเนื่องถึงด้านล่างภาพตามวิธีเดิม
ระยะพื้นปัดเป็น 5 ซม. เฉพาะช่วง 10–300 ซม. และยังอาศัยสมมติฐานพื้นเรียบกับค่ากล้อง ไม่ใช่การวัดจริงหรือการยืนยันว่าทางโล่ง

ข้อจำกัด: โมเดลยังมีเกณฑ์ความมั่นใจและขนาดภาพนำเข้า จึงไม่รับประกันว่าตรวจได้ทุกชิ้น
ของเล็กมาก ถูกบัง โปร่งใส หรือรูปลักษณ์ต่างจากข้อมูลฝึกอาจพลาดได้ และการจำแนกผิดอาจทำให้กรองวัตถุผิดประเภท
ต้องทดลองกับกระปุกไม้จิ้มฟันจริง ขวด กล่อง และเฟอร์นิเจอร์ ทั้งใกล้/ไกลและเมื่อมองไม่เห็นพื้น ก่อนสรุปความแม่นยำ

ตรวจ regression ของช่อง 3:

```bash
venv/bin/python -m unittest discover -s tests -p 'test_object_preview.py' -v
node tests/test_vision_dashboard.cjs
```

ค่ากล้องตั้งใน `.env` แล้วเริ่ม server ใหม่: `CAMERA_HEIGHT_CM` ความสูงเลนส์จากพื้น (5–200),
`CAMERA_TILT_DEG` มุมก้มจากแนวนอน (-45–89), `CAMERA_HFOV_DEG` มุมมองแนวนอน (20–170)
ค่าตั้งต้น 20, 15 และ 65 เป็นเพียงค่าสมมุติ ต้องวัดกล้องจริงก่อนเชื่อตัวเลข
ตัวเลขนี้ใช้แสดงผลเท่านั้น ไม่ถูกส่งให้โหมดขับอัตโนมัติและไม่เปลี่ยนการตัดสินใจของรถ

วิธีแยกพื้นเป็น heuristic จากระนาบความลึกในช่วงล่างของภาพด้วย RANSAC
สิ่งกีดขวางต้องทั้งอยู่ใกล้เชิงเปรียบเทียบและยื่นใกล้กว่าพื้นที่คาดไว้ ณ ตำแหน่งภาพนั้น
จึงไม่ใช้แค่ความใกล้ของพื้นล่างมาตัดสินว่ามีของ และไม่ใช่ semantic segmentation
หากหาระนาบพื้นไม่ได้ ยังตรวจบริเวณใกล้ที่มีขอบความลึกต่างจากฉากหลังโดยรอบได้
เมื่อขอบวัตถุใกล้เข้าช่องเฝ้าระวังจะเตือนแดงเฉพาะช่องนั้นได้แม้มองไม่เห็นพื้น เช่น ของชิดกล้องบังพื้น
ทางตรวจนี้เปรียบเทียบความลึกบริเวณขอบด้านในกับวงรอบด้านนอก
ความลึกที่ไล่ระดับเรียบ ๆ อย่างเดียวไม่ถือเป็นวัตถุ หากไม่พบหลักฐานใกล้และแยกพื้นไม่ได้
จะคงประเมินไม่ได้ ไม่มีการสรุปว่าทางว่างจากการตรวจขอบเพียงอย่างเดียว
กรอบวัตถุเป็นกรอบบริเวณความลึกผิดปกติ
ไม่ได้ระบุชนิด/ชื่อสิ่งของและไม่ได้รับประกันว่าจะครอบตัววัตถุครบทั้งชิ้น

วิธีทดลองจริง:

1. หันกล้องให้เห็นพื้นด้านหน้า มุมคงที่และแสงพอเหมาะ

4. ลองพื้นว่าง เงา พื้นลาย ขาโต๊ะเล็ก วัตถุสีเหมือนพื้น และกล้องเอียง
5. หยุด IP Webcam: ภาพเกินอายุ 3 วินาทีหรือการเชื่อมต่อขาด ต้องไม่แสดงผลเขียวว่าใช้ได้
   แล้วเริ่มกล้องใหม่ ภาพความลึกควรกลับมาเอง

เมื่อผลเก่า ภาพจริงจะกลับไปแสดงภาพกล้องล่าสุดและซ่อนภาพความลึกเก่า
การดูภาพและความลึกอย่างเดียวไม่ส่งคำสั่งรถ ต้องกดเริ่มขับอัตโนมัติก่อน

ข้อจำกัด: โมเดล relative depth ไม่ได้ให้ระยะจริงหรือความใกล้ที่เทียบข้ามฉากได้คงที่

## เชื่อมต่อหุ่นยนต์

ถ้าไม่ตั้ง `ROBOT_URL` หน้ารีโมทจะเปิดได้ แต่ปุ่มขับจะปิดไว้
เมื่อตัวบอร์ดรองรับ API ด้านล่างแล้ว ให้รัน:

```bash
ROBOT_URL=http://192.168.1.50 venv/bin/python main.py
```

หรือใส่ `ROBOT_URL=http://192.168.1.50` ในไฟล์ `.env` ที่โฟลเดอร์โปรเจกต์ แล้วรัน `venv/bin/python main.py`
ใช้ IP ของบอร์ดจริง หลังแก้ `.env` ต้องหยุดและเริ่ม server ใหม่
ค่าที่ตั้งใน Terminal จะมีลำดับความสำคัญก่อน `.env` และควรรัน server เพียงหนึ่ง process
ใช้ภายใน LAN ที่เชื่อถือได้ (ยังไม่มีระบบล็อกอิน)

Python ส่ง `POST /command` ไปยังบอร์ด โดยมี JSON เช่น `{"command":"forward"}`
คำสั่งที่รองรับ: `forward`, `backward`, `left`, `right`, `stop`
บอร์ดต้องตอบ HTTP 2xx พร้อมข้อความยืนยันคำสั่ง เช่น `forward`
หน้ารีโมทจะเปิดปุ่มขับเมื่อบอร์ดตอบรับ `stop` สำเร็จ
ถ้าส่งคำสั่งล้มเหลว ปุ่มขับจะปิด และต้องยืนยัน `stop` ใหม่ก่อนขับต่อ
รับรีโมทครั้งละหนึ่งหน้า ปล่อยปุ่ม/สลับหน้าต่างจะส่ง `stop`
หากไม่มีข้อความจากรีโมท 0.6 วินาที เซิร์ฟเวอร์จะตัดการเชื่อมต่อและพยายามส่ง `stop`

คัดลอก `robot/robot_config.example.h` เป็น `robot/robot_config.h` ใส่ชื่อ Wi-Fi/รหัสผ่านจริง (ไฟล์นี้ git-ignore)
แล้วอัปโหลด `.ino` ทั้งหมดใน `robot/` ลงบอร์ด ESP32

โค้ดใน `robot/remote.ino` มี API นี้แล้ว ต้องอัปโหลดโค้ดที่รองรับลงบอร์ดและทดสอบทิศทางมอเตอร์จริง
บอร์ดตรวจเวลาคำสั่งใน `loopRemote()` และสั่งหยุดมอเตอร์เมื่อไม่ได้รับคำสั่งที่ถูกต้องครบ 0.5 วินาที
ต้องอัปโหลดเฟิร์มแวร์เวอร์ชันนี้ลงบอร์ดก่อนจึงจะมีพฤติกรรมนี้ โดยเวลาหยุดจริงขึ้นกับเวลาที่ลูปกลับมาตรวจด้วย
ทดสอบโดยยกล้อ สั่งเดินหน้า แล้วหยุดส่งคำสั่ง ตรวจว่ามอเตอร์หยุดเอง และทดสอบซ้ำเมื่อตัด Wi-Fi หรือหยุด Python

## ขับอัตโนมัติจาก Dashboard

ตั้ง `CAMERA_URL` และ `ROBOT_URL` เริ่ม server หนึ่ง process แล้วเปิด `/dashboard`
ภาพและความลึกทำงานต่อเนื่อง แต่โหมดขับเริ่มต้นปิดเสมอ การเปิดหน้าใหม่/รีเฟรชไม่ทำให้รถเริ่มขับ
ปุ่ม **เริ่มขับอัตโนมัติ** ใช้ได้เมื่อมีภาพและผลวิเคราะห์สด และยังไม่มีผู้ควบคุมรถ
เมื่อกดเริ่ม Python ต้องได้รับคำตอบ `stop` จากบอร์ดก่อนจึงเปิดโหมด
หน้าจอแสดงคำสั่งที่บอร์ดตอบรับล่าสุดพร้อมเหตุผล การตอบรับไม่ใช่การวัดว่ามอเตอร์เคลื่อนจริง

| กรอบซ้าย | กรอบขวา | คำสั่ง |
|---|---|---|
| เขียว | เขียว | `forward` |
| แดง | เขียว | `right` |
| เขียว | แดง | `left` |
| แดง | แดง | `stop` แล้วเริ่มหมุนหาทางเป็นช่วง ๆ |
| เหลือง | เหลือง | `stop` รอผลสดต่อเนื่อง 3 วินาที แล้วหมุนขวาหาทาง |
| เหลืองข้างเดียว | อีกข้างแดงหรือเขียว | `stop` รอผลที่ประเมินได้ ไม่เริ่มหมุน |

เดินหน้า/เลี้ยวต้องมีผลทิศทางเดียวกัน 3 เฟรมวิเคราะห์ใหม่ติดต่อกัน
ไม่นับเฟรมเดิมซ้ำหรือเฟรมที่มีอยู่ก่อนกดเริ่ม ระหว่างยืนยันหรือเปลี่ยนทิศทางให้หยุดก่อน
เมื่อเหลืองทั้งสองข้าง รถหยุดรอให้ผลวิเคราะห์ใหม่ยังเป็นเหลืองทั้งคู่ต่อเนื่องอย่างน้อย 3 วินาที ก่อนเข้าการหมุนหาทาง
ถ้าเหลืองเพียงข้างเดียวให้หยุดรอ ไม่เริ่มหมุน; ถ้าข้างใดเปลี่ยนเป็นแดงหรือเขียวให้ล้างเวลารอ แล้วใช้กติกาของสีนั้น
ไม่นับเฟรมซ้ำหรือผลจากภาพเก่า ช่วงขาดภาพสดล้างเวลารอ กล้องหลุด/ผลเก่าจะปิด Auto ตามเงื่อนไขความสดด้านล่าง
ระหว่างรอเหลือง Auto ยังเปิดอยู่; หลังเริ่มหาทางแล้วใช้ขั้นตอนหมุนเดิม ไม่รอเหลืองอีก 3 วินาทีทุกช่วง
ไม่สั่งถอยหลังอัตโนมัติ กรอบเป็นบริเวณในภาพ ไม่ได้วัดขนาดทางให้พอดีตัวรถหรือระยะเบรกจริง

เมื่อแดงทั้งคู่ ระบบหยุดก่อนแล้วเลือกหมุนฝั่งที่มีสัดส่วนพิกเซลสิ่งกีดขวางในกรอบน้อยกว่า
ถ้าคะแนนเท่ากันเลือกขวา และคงทิศเดิมตลอดการหาทางรอบนั้น ไม่สลับตามคะแนนแต่ละเฟรม
คะแนน `obstacle_scores` อยู่ในช่วง 0–1 เป็นพื้นที่ในภาพ ไม่ใช่ระยะห่างหรือการรับรองว่าผ่านได้
ถ้าคะแนนหายหรือใช้ไม่ได้จะหยุดรอ ไม่เริ่มหมุน
หมุนครั้งละเป้าหมาย 0.2 วินาที แล้วส่งหยุดและรอผลจากภาพที่รับหลังบอร์ดตอบรับหยุดเท่านั้น
ไม่ใช้ภาพที่รับระหว่างหมุน แม้ผลวิเคราะห์จะเสร็จหลังหยุดแล้วก็ตาม
ถ้ายังมีด้านแดงหรือเหลืองให้ลองหมุนทิศเดิมต่อ สีเหลืองระหว่างหาทางไม่ทำให้ปิดโหมด
ถ้าเริ่มหาทางเพราะสีเหลืองเลือกขวาเสมอ ถ้าเริ่มเพราะแดงทั้งคู่ยังเลือกตามคะแนนข้างต้น
เมื่อเขียวทั้งคู่ครบ 3 เฟรมใหม่หลังหยุดติดกัน ให้หยุดค้นหาและเดินหน้าต่อทันที ไม่ต้องหมุนครบหนึ่งรอบ
ถ้าไม่พบทางจนใช้เวลาหมุนสะสมครบ ให้หยุดรอทางโล่ง โดย Auto ยังเปิดและยังครองสิทธิ์ควบคุม
ขณะหยุดรอจะไม่หมุนรอบใหม่เอง เขียวทั้งคู่ครบ 3 เฟรมใหม่จึงไปต่อได้ ไม่ต้องกดเริ่มใหม่
เฟรมเหลืองหรือแดงคั่นจะล้างจำนวนเฟรมเขียวที่ยืนยันไว้ ไม่สั่งถอยหลังเอง
Dashboard แสดงหยุดก่อนหาทาง กำลังหมุน หยุดรอภาพใหม่ และหยุดรอทางโล่งพร้อมเหตุผล

ตั้ง `AUTO_SPIN_SECONDS` ใน `.env` เป็นเวลาที่มอเตอร์หมุนสะสมสำหรับหนึ่งรอบโดยประมาณ แล้วเริ่ม server ใหม่
ค่าตั้งต้น **4.0 วินาทีเป็นเพียงค่าทดลอง ยังไม่ได้ปรับเทียบกับรถจริง** รับค่า 0.2–60 วินาที
นับเฉพาะช่วงเริ่มส่งหมุนจนบอร์ดตอบรับหยุด รวมความหน่วงส่งคำสั่ง แต่ไม่รวมช่วงหยุดดูภาพ
แต่ละช่วงหมุนไม่เกินเป้าหมาย 0.2 วินาที และช่วงสุดท้ายใช้เวลาคงเหลือของงบหมุน
ยกเลิกขีดจำกัดเดิม 4 ช่วง/10 วินาที เวลารวมการค้นหาอาจนานขึ้นตามความเร็ววิเคราะห์
ไม่มีเซนเซอร์วัดมุม จึงไม่ใช่การยืนยันว่าหมุนครบ 360°; พื้นและแบตเตอรี่ทำให้มุมคลาดเคลื่อนได้
ปรับเทียบในพื้นที่โล่งโดยทำเครื่องหมายทิศเริ่มต้น วัดเวลามอเตอร์หมุนจริงให้ครบหนึ่งรอบ (ไม่นับช่วงหยุด)
แล้วใส่เวลานั้นใน `AUTO_SPIN_SECONDS` และตรวจซ้ำกับการหมุนเป็นช่วงของ Auto
ระยะเวลาหมุนจริงอาจเกินเป้าหมายตามรอบควบคุม 0.1 วินาทีและเวลารับส่งคำสั่ง
ก่อนใช้งานต้องจูนกับรถจริงในพื้นที่โล่งมีคนดูแล กล้องหน้าไม่ยืนยันระยะด้านข้าง/หลังหรือพื้นที่กวาดตอนหมุน
การตอบรับ `stop` ยังไม่ใช่การวัดว่าตัวรถหยุดนิ่งจริง และเวลาในภาพคือเวลารับเฟรมบน server

ปุ่มแดง **หยุด** ปิดโหมดและส่ง `stop` ได้จากทุก Dashboard รวมถึงหยุดรีโมทที่ครองสิทธิ์อยู่
เมื่อมี AI ควบคุมอยู่ หน้ารีโมทจะเชื่อมต่อควบคุมไม่ได้ ต้องหยุดโหมดก่อน
เมื่อมีรีโมทครองสิทธิ์ ปุ่มเริ่มอัตโนมัติจะปิดไว้
ปิด/สลับแท็บหรือช่องภาพขาดการติดต่อ จะปิดโหมดและพยายามส่งหยุด
Python ตรวจ heartbeat จาก Dashboard เจ้าของโหมดทุก 0.1 วินาที ขาดเกิน 0.6 วินาทีจะปิดโหมด
Dashboard อื่นต่ออายุสิทธิ์แทนเจ้าของไม่ได้
ภาพหรือผลวิเคราะห์อายุครบ 3 วินาที กล้องหลุด โมเดลผิดพลาด หรือบอร์ดตอบไม่ตรง/ไม่ตอบรับ
จะปิดโหมดและพยายามส่งหยุด ต้องกดเริ่มใหม่หลังแก้ปัญหา การกลับมาเชื่อมต่อไม่เริ่มขับเอง
คำสั่ง HTTP แต่ละครั้งจำกัดเวลารวม 0.4 วินาที แต่เครือข่ายขาดอาจทำให้ส่งหยุดไม่สำเร็จ
การดู Dashboard อย่างเดียวและการเชื่อมต่อใหม่ไม่ส่งคำสั่งรถ

ทดสอบด้วยบอร์ด HTTP จำลอง (ไม่ส่งคำสั่งไปฮาร์ดแวร์):

```bash
venv/bin/python -m unittest discover -s tests -p 'test_auto_drive.py' -v
node tests/test_auto_dashboard.cjs
```

ยังต้องทดสอบกับรถจริง: ยกล้อก่อนเพื่อตรวจทิศทางและปุ่มหยุด แล้วทดลองสิ่งกีดขวางซ้าย/ขวา/ทั้งสอง
ตรวจการหยุดรอและไปต่อเอง รวมถึงภาพเก่า สลับแท็บ และบอร์ดไม่ตอบ
ยังไม่ยืนยันความแม่นยำและระยะหยุดจากการทดสอบข้อมูลจำลองเพียงอย่างเดียว
